# anore для BILLmanager 6

Модуль создаёт RUB- или USD-инвойс через API anore, переводит клиента на платёжную форму и зачисляет оплату в BILLmanager после проверки подписанного webhook. Он сверяет сумму, валюту, UUID и номер заказа, проверяет доступ клиента к платежу и сохраняет историю попыток оплаты.

## Требования

- BILLmanager 6 в `/usr/local/mgr5`;
- PHP 7.4+ CLI в `/usr/bin/php` с расширениями cURL, JSON, SimpleXML и mysqli;
- разрешённая PHP-функция `exec` для вызова `mgrctl`;
- библиотека BILLmanager `/usr/local/mgr5/include/php/bill_util.php`;
- публичный HTTPS-домен BILLmanager;
- API-ключ anore и секрет webhook нужного магазина.

CGI-скрипты работают через PHP CLI: читают HTTP-запрос из STDIN и выводят CGI-заголовки. PHP-CGI и изменения базы данных не требуются. Другой каталог установки BILLmanager не поддерживается: `bill_util.php` использует `/usr/local/mgr5`.

## Установка

На сервере BILLmanager:

```bash
git clone https://github.com/ANORE-PAYMENTS/billmanager6-module.git
cd billmanager6-module
sudo bash install.sh
```

Установщик проверяет зависимости, синтаксис PHP и XML до замены файлов, устанавливает модуль и перезапускает BILLmanager. Вспомогательную библиотеку `bill_util.php` он не заменяет.

Откройте `Провайдер → Способы оплаты`, добавьте `anore` и заполните:

- `Адрес API`: `https://api.anore.cc` или оставьте пустым. Адрес с окончанием `/api/v1` тоже принимается;
- `API-ключ`: ключ магазина или аккаунта;
- `Секрет API`: необязательный секрет подписи `X-ZPay-Signature` этого API-ключа;
- `Секрет вебхука`: тот же секрет, который указан в настройках магазина anore;
- `ID магазина`: обязателен для ключа уровня аккаунта; для ключа магазина оставьте пустым;
- `Методы оплаты`: пустое поле использует настройки магазина. Можно указать `sbp,card,yoomoney,crypto,crypto-old`. Псевдонимы `dvnet` и `xrocket` приводятся к `crypto` и `crypto-old`; повторы удаляются.

Выбранные методы должны быть разрешены для магазина anore. Валюта платёжного метода BILLmanager должна быть RUB или USD. Валидный email клиента передаётся в API для чека.

## Обновление

На том же сервере, в каталоге ранее клонированного модуля:

```bash
git pull --ff-only origin main
sudo bash install.sh
```

Настройки платёжного метода и история в `/usr/local/mgr5/var/anore-payments` сохраняются. Старые файлы сопоставлений поддерживаются и переводятся в новый формат при обработке. Сохраняются прежние пути CGI и формат `orderId`, поэтому созданные ранее инвойсы продолжают обрабатываться.

## Webhook

В настройках нужного магазина anore задайте секрет webhook, совпадающий с полем в BILLmanager. Для совместимости с ранее созданными инвойсами сохраните адрес:

```text
https://ВАШ-ДОМЕН-BILLMANAGER/mancgi/anoreresult.php
```

Для новых инвойсов модуль передаёт отдельный `callbackUrl` с параметром `payment`, чтобы направлять уведомления в нужный платёж BILLmanager. Этот адрес имеет приоритет над общим адресом магазина. Подпись `Anore-Signature` проверяется по исходному телу запроса с HMAC-SHA256.

`payment.succeeded` зачисляет оплату, `payment.expired` отмечает попытку истёкшей. Запоздалое событие об истечении не отменяет подтверждённую оплату. Проверочное событие `payment.test` с параметром `payment` проверяет подпись без изменения статуса платежа.

При повторном webhook модуль проверяет статус BILLmanager и сохранённый `externalid`. Ошибка `mgrctl` или записи состояния не подтверждается как успешно обработанная: временная ошибка возвращает HTTP 503 для повторной доставки.

## Повторные попытки и восстановление

Повторное открытие действующего инвойса возвращает сохранённую ссылку. Если до его истечения изменились сумма, валюта, email, магазин или настройки платёжного метода, модуль возвращает HTTP 409 и не создаёт второй действующий инвойс. Дождитесь истечения первого инвойса; если нужна срочная отмена, сначала подтвердите её в anore и выполните сверку с поддержкой. Команда восстановления ниже предназначена только для незавершённого запроса создания, а не для сброса действующей ссылки.

После истечения можно создать новую попытку. Предыдущие попытки сохраняются в истории, чтобы позднее уведомление оставалось связано с исходным UUID. Поздняя успешная оплата зачисляется, если текущая сумма, валюта и платёжный метод BILLmanager совпадают с сохранёнными данными. При расхождении модуль возвращает HTTP 422: нужна ручная сверка, автоматическое зачисление по изменённым данным не выполняется. Если один платёж BILLmanager уже зачислен по другому UUID, повторная успешная оплата также требует ручной сверки.

Файлы состояния и индексы UUID находятся в `/usr/local/mgr5/var/anore-payments`. Повреждённое сопоставление блокирует автоматическое создание нового инвойса.

Если соединение оборвалось при создании инвойса, автоматический повтор блокируется: API не гарантирует уникальность инвойса по `orderId`. Сначала проверьте платежи в кабинете anore по номеру заказа и времени попытки.

Только после подтверждения, что инвойс **не был создан**, снимите блокировку конкретного платежа:

```bash
sudo /usr/bin/php /usr/local/mgr5/paymethods/anore-recover.php \
  --payment=123 --confirm-not-created
```

Замените `123` на ID платежа BILLmanager. Команда сбрасывает только последнюю незавершённую инициализацию и сохраняет историю. Если инвойс уже существует в anore, не применяйте этот сброс: сверьте его UUID и результат оплаты. Не удаляйте JSON вручную — это теряет сопоставления и может создать вторую оплату.

## Проверки для разработчиков

Из каталога модуля:

```bash
PHP_BINARY=/usr/bin/php node tests/http.mjs
```

Нужны Node.js и OpenSSL; при необходимости задайте `OPENSSL_BINARY`. Проверки запускают реальные PHP CLI CGI-процессы и локальный HTTPS API, проверяя редиректы, подписи, отказ авторизации, повторные уведомления, ошибки зачисления и сохранения состояния. Сервер BILLmanager и API-ключи для этих проверок не нужны.

## Удаление

```bash
sudo bash uninstall.sh
```

История сопоставлений и библиотека `bill_util.php` сохраняются.
